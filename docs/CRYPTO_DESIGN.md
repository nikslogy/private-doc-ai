# Vault cryptography and durability

This describes the current vault source in `platform/.../vault`, not a completed or audited vault. Android compilation, native SQLCipher loading, Keystore authentication, ciphertext compatibility and physical-device leakage checks remain release gates in [DEVICE_TESTS.md](DEVICE_TESTS.md). No recovery, key rotation or encrypted backup is implemented. The Room metadata migration described below is authored but has no device execution evidence.

## Threat boundary and storage

The vault stores application data under `Context.noBackupFilesDir/private-vault-v1`. Originals are opaque encrypted objects named with random revision UUIDs; document names, MIME types, sizes, timestamps, SHA-256 deduplication hashes and extracted evidence reside in the encrypted SQLCipher Room database. Neither object names nor root metadata contain content hashes or document names. Source SAF URIs and durable source permissions are not retained. Root/streaming keysets and the database secret are persisted only as authenticated ciphertext. Plaintext original bytes, parser results and usable keys exist transiently in process memory; this does not protect an unlocked, compromised process, rooted device or an authorized export recipient.

Android backup exclusion and the app's manifest/data-extraction rules supplement `noBackupFilesDir`. App-private storage and authenticated encryption do not establish protection against every platform/OEM backup or a forensic attacker; verify the actual APK and devices. Ciphertext sizes, object counts and filesystem timing remain observable. The code does not provide rollback detection for a consistent older vault snapshot, cryptographic erasure guarantees or a recovery credential.

## Key hierarchy and public APIs

1. Android Keystore alias `<package>.vault.root.v1` holds an AES-256-GCM wrapping key, with randomized encryption, no padding and mandatory device credential or strong biometric authentication. Its authentication validity window is 30 seconds. The source uses `KeyGenParameterSpec` and `AndroidKeystoreKmsClient().getAead("android-keystore://<alias>")`.
2. A fresh Tink `AES256_GCM` root keyset is encrypted by that Keystore AEAD. Its random vault UUID is authenticated as associated data. The root AEAD independently encrypts a random 32-byte SQLCipher passphrase and the separate Streaming AEAD keyset, under distinct domain labels.
3. The Streaming AEAD keyset uses Tink `AES256_GCM_HKDF_1MB`. This primitive encrypts originals with an independent random salt/stream header and authenticated segments. The application does not invent a cipher, KDF or nonce format.

Tink is pinned to 1.17.0. The implementation registers `AeadConfig`/`StreamingAeadConfig`, creates handles with `KeysetHandle.generateNew`, and calls `getPrimitive`. Encrypted keyset serialization uses `writeWithAssociatedData(BinaryKeysetWriter, Aead, associatedData)` and `readWithAssociatedData(BinaryKeysetReader, Aead, associatedData)`. Tagged source review on 19 October corrected nine invalid three-argument `read`/`write` calls; their purpose-bound AAD and intended envelope format are unchanged. No cleartext keyset serialization or `subtle` API is used. Android dependency-resolution/compilation and Keystore/device behavior remain unverified. `DurableFiles.atomicWrite` passes a close-shielded stream to serialization callbacks, keeping the underlying descriptor open for `fd.sync()` even if a library writer closes its stream.

The SQLCipher integration uses `net.zetetic.database.sqlcipher.SupportOpenHelperFactory(databaseKey)` with the pinned 4.9.0 dependency. Opening the writable database forces passphrase consumption before the application's `ByteArray` is zeroed. Constructor and ownership behavior also require the dependency/device gate. Root and streaming Tink primitives keep internal key material in memory; JVM/ART and native copies cannot be reliably zeroed by application code.

## Associated data and envelope formats

All labels are UTF-8. UUIDs are generated randomly; object IDs used in file paths are validated against canonical lowercase UUID syntax.

| Artifact | Associated data | On-disk encoding |
| --- | --- | --- |
| `root.envelope` | `private-assistant/root/v1/<vault UUID>` | Big-endian `PAV1` magic integer, format integer `1`, Java `writeUTF` vault UUID, big-endian encrypted-keyset length, Tink binary encrypted keyset |
| `database.envelope` | `private-assistant/database-secret/v1/<vault UUID>` | Root AEAD ciphertext of exactly 32 random plaintext bytes |
| `streaming.envelope` | `private-assistant/streaming-keyset/v1/<vault UUID>` | Tink binary encrypted Streaming AEAD keyset under the root AEAD |
| `objects/<revision UUID>.blob` | `private-assistant/original/v1/<vault UUID>/<document UUID>/<revision UUID>` | Tink Streaming AEAD ciphertext |

Root envelope parsing checks magic, version, UUID, a bounded encrypted payload (28 bytes through 64 KiB) and exact EOF. The other envelopes have the same file-size bound. Root AAD binds the clear vault UUID and format domain; changing the UUID fails authentication. Domain labels prevent exchanging database and streaming envelopes. Original AAD prevents exchanging ciphertext between vaults, documents or revisions. This foundation stores one immutable original revision per document; future derivatives require independent domain labels and versioned metadata.

## Unlock and lock

The caller invokes unlock after successful system authentication. A missing Keystore alias or root envelope fails closed when pre-existing vault artifacts are present. Missing child envelopes may be created only when no metadata database or original object exists, permitting an interrupted first setup to finish without replacing keys for stored documents. Invalid authentication, envelope corruption and permanent key invalidation preserve existing files; there is no automatic destructive reset.

Unlock decrypts secrets, opens SQLCipher, applies memory security/secure deletion/in-memory temp storage/full synchronization pragmas, and validates the index before cleaning ciphertext orphans. `TRUNCATE` journal mode is selected. The controller publishes an unlocked session only after recovery succeeds. The passphrase buffer is cleared on both success and failure. Closing a failed open database is mandatory.

The shared `VaultDatabaseSecurity` callback is also used by the actual SQLCipher
and migration regression tests. `PRAGMA secure_delete = ON` returns a row in
SQLCipher 4.9.0, so it must use a cursor query, consume the result and verify `1`.
Using `execSQL` rejects that row and prevented the original debug APK's first
database open. The other non-result setting statements retain `execSQL`.
This API correction changes no key, authentication policy or envelope format.

`lock()` clears the controller's active session, advances its epoch, sets the state to locked and closes SQLCipher. A concurrent unlock must match that epoch before publishing a session. Operations check the active session between buffers and before publication. Dropping Tink references is best effort memory hygiene. Locking the app does not revoke Android's remaining 30-second authentication window; UI/session rules must still require the intended unlock flow. A blocked ContentProvider read or native/parser call may continue until it returns; lock/cancellation is cooperative and cannot promise instantaneous interruption or immediate erasure of all live buffers.

A process-wide mutex serializes vault open/recovery and document operations across controller instances. Without this, a second activity's recovery could remove a first activity's ciphertext between publication and metadata commit. The current application has no separate Android processing service; a future additional process requires cross-process coordination before it can use this storage.

## Import, publication and recovery

Import streams provider bytes through a 64 KiB buffer directly into `staging/<revision UUID>.part` ciphertext, computing SHA-256 in memory and enforcing the 25 MiB limit. The plaintext buffer is cleared in `finally`. Content hashes are persisted only inside the encrypted database and have a unique index. A same-content import returns the existing document; its staged ciphertext is removed.

Before publication, the complete staged ciphertext is decrypted to a bounded RAM buffer and consumed through EOF, then checked by `MemoryDocumentParser` for actual file type/signature, UTF-8/PDF validity and page/image limits. This validation intentionally allocates plaintext memory, never a plaintext parser file. The buffer is cleared in `finally`; parsed strings and library/native allocations are subject to garbage collection. The parser's approximately 15-second checks are cooperative between operations/pages, not a hard timeout around blocked native execution. Native PDF/UTF-8 page text and page geometry are published with metadata in the same encrypted transaction. Raster pages remain labelled as requiring OCR; importing does not start a recognizer.

The encrypting stream is finalized before the file descriptor is synced. The staged ciphertext is then renamed into the object directory, that directory is synced, and only then is its Room metadata row committed. Atomic envelope writes likewise sync a temporary ciphertext file, rename it and sync its parent. There is no intended durable metadata row pointing to an incomplete object. A crash after object publication and before metadata commit leaves encrypted orphan data. The controller deletes a newly published object on a failed uncommitted import, and never deletes a committed object merely because cancellation/lock follows the transaction.

Recovery runs only after a successful encrypted database open and complete index read. It rejects missing referenced objects before deleting anything. It removes recognized UUID staging files, recognized unreferenced UUID object files and abandoned `.atomic-` envelope files. It does not try to reconstruct missing referenced ciphertext or authenticate every full original during unlock. Deletion commits metadata removal first and unlinks ciphertext afterward; recovery handles an interrupted unlink. Exercise crash windows on real filesystems, including persistence of newly created directories and atomic writes.

## Encrypted evidence and Room schema 2

The explicit Room migration from schema 1 to 2 adds a page count (initially zero) and `NOT_INDEXED` status to existing documents, then creates page evidence, source-span and FTS4 tables. It does not change the SQLCipher secret, object format, AAD, immutable revision IDs, original bytes or digests. There is no destructive migration fallback and no automatic reindex on unlock. The filesystem directory and crypto envelope version remain v1 because their formats are unchanged. Room validates the migrated schema when opened; an invalid migration fails closed.

Evidence stores original UTF-16 text, immutable document/revision/page identity, extraction method/version, page dimensions and optional bounded source boxes/spans. The ASCII terms in the FTS4 index are reversibly encoded lexical tokens, so they are private content too: they remain inside SQLCipher, including FTS shadow tables and journal pages. Token encoding only avoids discrepancies between SQLite Unicode tokenizers and the application's source tokenizer; it is not encryption. Queries are bounded literal all-term requests encoded by that same tokenizer, never raw user `MATCH` syntax. Each hit is checked against the exact stored page and returns a bounded original quote with UTF-16 offsets. Search inspects at most 200 candidate pages and returns at most 50 hits; this is lexical retrieval, with no semantic/identity/current-policy claim.

Publication and replacement of page rows, source spans, FTS rows and index state occur in one transaction, with session and coroutine cancellation checks immediately before and after the writes. The session monitor prevents a lock from closing the database within that transaction; cancellation rolls it back before commit when observed. An explicit native reindex decrypts and validates the entire original/digest in RAM before parsing. Missing OCR stays `NEEDS_OCR`; unsuccessful OCR preserves prior nonblank evidence and reports partial/failed indexing. Native-only refreshes preserve already valid OCR from the same immutable original. Cancellation retains previous evidence/status. A lock prevents an old session from publishing into a later session. A process-death `INDEXING` status becomes `FAILED` at next unlock, awaiting explicit retry; it does not schedule background plaintext processing.

Document deletion removes its FTS rows and document row in the same transaction; foreign-key cascades remove evidence and spans. Ciphertext original unlink follows commit, with orphan cleanup on restart. The migration/search integration test uses actual SQLCipher and verifies schema validation, preserved IDs/digest/object bytes, Devanagari combining marks, leading-zero identifiers, literal operator words, exact citations, rollback, reopen, cascading deletion and plaintext/encoded-token canary absence. It is authored, not run. The opt-in authenticated lifecycle probe also checks persisted native evidence and locked search; real lock/cancel/process-death races and disk/log canary inspection remain pending.

## Read/export integrity and remaining gates

`copyOriginalTo` checks per-segment Streaming AEAD authentication and consumes the stream through EOF, then verifies plaintext byte count and SHA-256 against encrypted metadata. Reading only a prefix would authenticate only the consumed segments; opening a stream alone is not whole-file verification. Export writes authenticated earlier segments before the final whole-file checks, so failure, lock or cancellation may leave partial plaintext in the external destination. The caller owns that output and must remove incomplete output; later share/export flows must expose a completed result only after validation and explicit user action.

Required verification includes first setup with no prior authentication, successful/wrong/expired authentication, key invalidation, lock during unlock/import/export, process death at every publication boundary, duplicate import, exact original round trips, cross-vault/document/revision swaps, envelope tampering, truncated/appended ciphertext, wrong secrets/AAD, missing objects and recovery preservation. Inspect database journals, application files/caches/logs and backup output using synthetic plaintext canaries. Confirm secure-screen/lifecycle enforcement in the app, SQLCipher native compatibility and encrypted keyset durable writes. These gates are pending until actual test evidence is recorded; a source review is not an M1 completion claim.

Platform instrumentation test sources have been authored for real Tink streaming/keyset behavior, SQLCipher encryption, and production Keystore key-generation policy. They have not run in this environment. The Keystore policy test skips devices without a secure screen lock; a skip is not authentication validation. The policy test alone does not establish successful biometric/device-credential unlock behavior.

`VaultLifecycleInstrumentedTest` is an additional opt-in test of the real controller, Keystore, Tink and SQLCipher. It uses an isolated test directory/alias and a synthetic Android resource URI, with no plaintext staging file or substitute encryption. It checks exact original bytes, deduplication, lock, controller recreation, staged/orphan ciphertext cleanup, preservation when a referenced object is missing, canary absence in private artifacts and deletion that leaves the source untouched. This simulates interrupted-publication artifacts; it does not establish actual process-death/power-loss durability. Default runs skip this test because it requires a real system authentication token. Configure a secure device lock, authenticate immediately before running, select only this test class, and opt in with `-e runAuthenticatedVaultLifecycle true`. Authentication expiration is a test failure, never a fallback to an unprotected key. Confirm the installed instrumentation package with `adb -s "$ANDROID_SERIAL" shell pm list instrumentation` before running it. No execution of this probe has been recorded yet.
